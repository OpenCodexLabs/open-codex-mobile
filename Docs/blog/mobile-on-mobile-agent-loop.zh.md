# Mobile-on-Mobile Agent Loop：让手机端 Codex 指挥电脑，再反过来操作这台手机

这次实验验证了一个有点反直觉的闭环：用户在手机端 Codex 里发指令，电脑端 Codex 接收任务，然后通过 USB ADB 操作这台手机本身的真实 GUI。

一句话说：

> 手机既是控制端，也是被控端；电脑只是执行桥。

## 为什么这个实验有意思

过去我们通常把手机理解成 Agent 的遥控器。比如人在路上，用手机查看桌面 Codex 的进度，批准命令，补充上下文。

但这次多了一层：手机不只是遥控器，它也是任务对象。手机端发出指令后，电脑端 Agent 可以打开同一台手机上的高德、浏览器、微信、文件 App，像人一样看屏幕、点按钮、读结果、截图确认。

这个 loop 是：

```text
手机端 Codex 发任务
-> 电脑端 Codex 接收
-> 电脑通过 USB ADB 操作手机
-> 手机 App 被真实点击和读取
-> 结果回到手机端 Codex
```

## Demo：查去大湾区大学要多久

我选了一个生活任务做验证：从当前位置到“大湾区大学（松山湖校区）”，用高德地图看路线和用时。

实际结果：

- 高德搜索到了东莞的“大湾区大学（松山湖校区）”。
- 驾车路线显示约 50 公里，最快约 57 分钟。
- 顺风车/叫车类页面显示约 48.2 公里，约 56-57 分钟。
- 没有进行下单、支付、打电话或任何不可逆操作。

这个任务足够生活化，也足够能验证闭环：它不是在命令行里打印一句话，而是真的让 Agent 操作了手机上的真实 App。

## 关键启发

第一，手机 GUI 可以成为 Agent 的真实行动面。很多服务没有开放 API，但手机 App 本身就是一个可操作界面。Agent 不一定要等 API，它可以先像人一样操作 GUI。

第二，Skill 的价值不是“让它能做”，而是“让它安全稳定地做”。裸 ADB 已经能打开 App、截图、点按、输入。真正需要沉淀的是工作流：先截图、读 UI、操作、再截图，遇到支付/下单/发送就停住。

第三，MCP 可以后置。只有当多个 Agent、多个手机、多个任务都要复用这套能力时，才需要把 `open_app`、`tap`、`screenshot`、`dump_ui` 封成 MCP。实验阶段不需要先重平台。

第四，这不是简单的远程控制。它展示的是一种跨设备 Agent 协作结构：手机负责意图，电脑负责执行，真实 App 负责承载现实任务。

## 边界

这个实验现在最好理解为一个启发性 workflow，不是成熟产品。

目前适合：

- 查询路线、天气、页面状态。
- 打开 App、搜索信息、截图留证。
- 做低风险、可回退的手机 GUI 操作。

不应该自动做：

- 支付、叫车、下单、发消息。
- 删除数据、修改账号设置。
- 授权隐私权限或安全权限。

## 结论

Mobile-on-Mobile Agent Loop 展示了一个未来可能：手机端 Agent 不只是聊天入口，它可以指挥桌面 Agent 去操作真实手机 GUI。

这不是为了替代 App API，也不是为了做一个复杂自动化平台。它更像一个小而清晰的实验：当手机、桌面 Agent 和 ADB 连起来后，真实世界的 App 任务可以被纳入 Agent workflow。

下一步不是急着做大软件，而是把这套模式沉淀成可复现的实验、清晰的安全规则，以及少量可复用 workflow。
